CineLog API in motion

Every request to CineLog passes the same five checks inside Engine E4 (CN & Web Tech), in the same order. Pick who is calling, the request and the situation, then press Play. The first check that fails decides the status code, and nothing after it runs. These checks are now built in backend/app/security.py, rbac.py and the routers on branch sprint-2. Under every answer, In the build shows the real route, the reply the code gives today and the recorded exchange or test (A01–A29 in docs/sprint2/evidence/api). Most answers match the design; where the build chose a different path or code, it says so.

All nine requests are now built. Some paths changed from the design: suggestions are GET /films/autocomplete, reviews are posted under the film (POST /films/{id}/reviews), votes go to /polls/{id}/vote and roles use POST. 422 from the framework was replaced by 400 with the field name (DEF-09). 503 is used today only when the TMDB key is missing; a 503 for an unavailable database is planned. Still open for Sprint 3: OWASP ZAP scan and HTTPS deployment (NFR-06).
